## 1. 背景与目标

Project.md 自 2026-08-14 起随每次代码变更同步维护，经 7 次以上迭代累积，经 Explore 阶段对照代码库实测（go version / git log / dist 体积），确认存在三类问题：

- **事实错误**（可机械验证）：
  - §2 Go 运行时写 `1.25.3`，本机实测 `go1.27.0`（`~/.local/go/bin/go`）；CI 用 `1.25.x`，`go.mod` 最低 `1.25.0`
  - §6 目录解析条目日期 `2026-08-18` 与 `2025-06-01`，git 实测两处修复（commit `2e51927` / `731b3fb`）均为 `2026-08-16`；`2025-06-01` 为跨年笔误（项目 2026-08-14 才开始）
  - §2 `npm run build` 产物体积写 `约 1.3MB`，实测 `frontend/dist` 为 `3.2MB`（KaTeX 1.2M + fonts 1.2M + app.js 796K）
- **表达冗余**：§6 目录解析条目为连环叙述（split 修复 → 同次遗漏 → 补充修复），过程流水账掩盖根因
- **过时标注**：§6 多实例条目 `v1.2 已知限制` 与当前 v1.5 阶段脱节；§3 `build/bin/mado.exe ~15.6MB` 为本机无法验证的 v1 时期数据

**目标**：以 clean-refactoring 四项公理为准绳——根因处修正事实、克制精简叙述、最短有效差分（不动文档既有结构，只改错误与冗余）、保持正交（不改 SCOPE.md / AGENTS.md / 代码）。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 事实修正范围 | 仅改可机械验证项（版本/日期/体积） | 最短差分，杜绝主观重写引入新偏差 | 全文重写（漂移风险大，违背克制原则） |
| §6 精简策略 | 保留根因与修复结论，压缩过程叙述 | 踩坑信息是核心价值，流水账是噪音 | 整节重排（破坏现有结构，响应面过大） |
| 无法验证数据 | 删除或改描述性说明（exe 体积） | 写死的旧数字比"约数"更误导 | 保留原数字（已知失真） |
