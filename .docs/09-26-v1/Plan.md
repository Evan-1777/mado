## 1. 背景与目标

Fluent 2 双主题重构（09-25-v3）交付后遗留三处缺口，本轮集中修复：

1. **设置面板停靠窗口左上角**（用户报告「设置不居中」）。根因已实测确认：外壳全局重置 `* { margin: 0 }` 覆盖了浏览器对模态对话框内置的 `margin: auto`，两个原生 `<dialog>`（设置、未保存确认）同时失去居中；元素 `position/inset` 正常，仅外边距被清零。
2. **编辑区行号槽数字未居中**（用户确认）。行号槽只承载数字（折叠箭头已下线），但数字沿用 CodeMirror baseTheme 的右对齐与非对称内边距（左 5px / 右 3px），视觉重心偏右，且行号槽宽度随位数漂移。
3. **预览围栏代码块无复制入口**。渲染层不输出任何复制控件，用户只能手动划选。

目标：

- 两个原生模态恢复窗口居中，Esc、焦点捕获与 submitter 返回值契约不变。
- 编辑区行号槽数字在行号槽内水平居中（左右留白相等）。
- 预览中每个围栏代码块提供复制按钮：悬停或键盘聚焦时出现，点击写入系统剪贴板并回显「已复制」。

**范围取舍（已确认）**：复制覆盖围栏代码块（含 ``` 与 ~~~ 两种围栏、带/不带语言、`{nohl=true}`），不含四空格缩进代码块。

理由是锚点与复制入口共用围栏包装层 `div.md-line`：复制分支才能沿用既有帧内委托点击监听并随 `innerHTML` 更新存活。goldmark 对缩进代码块走独立的 `renderCodeBlock`，无包装层、无 `data-line`（行号护栏同样跳过该块），要覆盖它就得为它补一套包装层——而那会改变行号锚点的既有边界，收益不抵改动成本。

非目标：不改动源行号锚点、双向跳转、预览行号栏（body 左留白的 CSS 数字）与 iframe 原地更新机制；不新增依赖；不改 Markdown 渲染语义与安全边界。

## 2. 阶段划分

### Phase 1：原生模态恢复窗口居中

| 项目 | 内容 |
|------|------|
| **输入** | 外壳样式中两个原生 `<dialog>` 的共享规则、全局重置的实际效果 |
| **输出** | 恢复内置自动外边距的对话框共享规则 |
| **验收标准** | 设置与未保存确认两个模态在窗口中水平垂直居中；Esc、焦点捕获、submitter 返回值行为不变 |

### Phase 2：编辑区行号槽数字水平居中

| 项目 | 内容 |
|------|------|
| **输入** | CodeMirror baseTheme 对行号单元的内边距与对齐默认值 |
| **输出** | 外壳覆盖规则：行号单元内边距左右对称、文本居中对齐 |
| **验收标准** | 行号数字左右留白相等（误差 ≤ 1px）；多位行号不产生抖动；行号槽右边界与跳转命中判定不变 |

### Phase 3：围栏代码块复制

| 项目 | 内容 |
|------|------|
| **输入** | 渲染层围栏包装层（`div.md-line`）、预览渐进样式表、前端帧内委托点击通道 |
| **输出** | 包装层内置复制按钮 + 预览样式 + 前端委托复制与反馈 |
| **验收标准** | 每个围栏代码块在悬停/聚焦时显示复制按钮；点击后系统剪贴板得到去除尾部换行的代码文本并回显「已复制」；无词法分析器与 `{nohl=true}` 的围栏同样具备按钮；Chroma 既有输出逐字不变 |

### Phase 4：契约测试同步与回归

| 项目 | 内容 |
|------|------|
| **输入** | 前三阶段全部变更、既有 Go 用例、UI 契约自检与 dev-only 无头自检 |
| **输出** | 同步后的渲染用例、UI 契约与复制的无头用例；构建与全量测试通过；Project.md 与归档更新 |
| **验收标准** | `npm test`、`go vet ./...`、`go test ./...`、`npm run build` 全部通过；复制无头用例与既有 dev-only 自检全部 `ALL PASS`；Project.md 与代码实际状态一致 |

**验证路径取舍**：居中类缺陷属几何量，无头断言须自建页面级夹具才有意义，而两者的根因都是单一 CSS 声明（模态被清零的自动外边距、行号单元的右对齐）——静态契约断言直接钉住根因即足以守卫回归，几何观感由一次人工核对确认。复制是行为链路（取文本 → 写剪贴板 → 回显还原），静态断言覆盖不到，故落在既有 dev-only 无头自检中，复用其 Wails 桩与 HTTP 夹具，不新建框架。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 模态居中修复点 | 在外壳对话框中恢复自动外边距 | 根因是全局重置清零外边距；共享规则单点修复，两个模态同时生效 | 给通用重置加 `dialog` 例外（扩大通用重置影响面）；为两个对话框各写一条规则（重复且易漂移） |
| 行号居中实现 | 外壳覆盖行号单元的内边距与文本对齐 | 行号槽已无折叠箭头、只承载数字，左右等距的四像素内边距即是居中所要求的全部几何；以 `:root[data-theme]` 提升特异性压过 baseTheme 默认 | 设固定 `min-width` 居中（它只是下限，拦不住更宽的数字，还引入无需要的宽度常量）；改用 CodeMirror 扩展参数（无对应参数） |
| 复制按钮注入点 | 渲染层在围栏包装层内输出按钮 | 包装层是唯一自有的围栏包裹元素，随渲染天然存在；iframe 原地更新无需二次扫描 | 前端渲染后遍历插入（每次正文更新都要重扫）；改 Chroma 输出（不受控） |
| 剪贴板通道 | Wails 运行时 `ClipboardSetText` | 仓库已生成该绑定，零新增依赖，走桌面原生剪贴板 | 浏览器 `navigator.clipboard`（帧无 `allow-scripts`，权限与用户激活语义不确定） |
| 复制事件绑定 | 复用帧文档既有的委托点击监听 | 该监听挂在帧 document 上、跨 `innerHTML` 更新存活，零新增监听与重挂逻辑 | 逐按钮绑定（正文重建即失效，需在每次渲染后重挂） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 剪贴板写入依赖 Wails 运行时绑定 | 🟢 低 | 写入失败静默返回、不改动界面结构；无头自检以 stub 覆盖写入路径 |
| 帧内无脚本执行权限，按钮点击须由父侧委托处理 | 🟢 低 | 复用既有跨帧委托点击路径（行号跳转已在同路径验证） |
| 行号槽宽度变化影响既有跳转命中判定 | 🟢 低 | 跳转按行号槽矩形与坐标判定，宽度自适应 |
| 复制按钮遮挡代码块首行内容 | 🟢 低 | 按钮仅在悬停/聚焦时可见，且贴代码块右上角 |
| 全局重置对其它原生元素的内置外边距影响 | 🟢 低 | 仅对话框依赖内置居中；本次不扩大通用重置的改动范围 |
| 居中类缺陷无自动化几何断言 | 🟢 低 | 根因是单一 CSS 声明，静态契约断言钉住该声明；几何观感在 Windows 主机人工核对一次 |
