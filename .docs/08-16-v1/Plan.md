# Plan：修复目录锚点链接不响应跳转

**状态**：DONE
**日期**：2026-08-16
**版本**：v1.0
**回归测试结论**：`go test ./...` 全部通过；新增 id/slug 用例通过；esbuild 语法检查通过（前端无改动，仅确认无回归）。

---

## 1. 背景与目标

中文文档的目录链接（如 `[先搞清楚 WSL 是什么](#一先搞清楚-wsl-是什么)`）点击后无任何响应。

根因：goldmark 自动标题 id 生成器（`parser/atx_heading.go` 的 `generateAutoHeadingID` → `ids.Generate`）只保留 ASCII 字母数字，**其余字符（含全部中文字符）一律丢弃**。于是：

- `## 一、先搞清楚 WSL 是什么` 生成的 id 是 `heading`（内容无 ASCII 字符时退化为此默认值）
- `## 环境搭建与安装` 生成的 id 是 `环境搭建与安装`（无任何分隔符，连中文"与"前都没有 `-`）

而用户文档中手写的目录 href 采用常见 slug 格式 `#一先搞清楚-wsl-是什么`（中文保留 + 全角标点转 `-`）。两端格式不一致，前端 `getElementById(href.slice(1))` 必然查不到 → 点击被拦截且不滚动，表现为"无响应"。

目标：让 goldmark 生成的标题 id 与主流 slug 格式（中文保留、全角标点/空白转 `-`、ASCII 小写）一致，使 `id` 与手写目录 href 精确匹配。修复点在 `internal/mdrender`，前端 `hookPreviewLinks` 的查表逻辑无需改动。

## 2. 阶段划分

| **验收标准** | 用户示例中的标题渲染出的 id 与目录 href 一一匹配 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 修复位置 | 后端 mdrender 自定义 ID 生成器 | 前端只做查表；后端改 slug 格式一处生效，保证 id/href 一致 | 前端做模糊匹配（收集所有 heading 做归一化比对）——逻辑复制到前端、双份维护，且 href 含非 ASCII 时 `document.querySelector` 需转义，复杂度高 |
| slug 规则 | 中文保留 + 全角标点/空白→`-` + ASCII 小写 + 重复加 `-N` | 与主流渲染器（GitHub 等）及用户手写目录的常见格式一致 | 严格 ASCII 化（如转拼音）——破坏现有英文锚点兼容性 |
| ID 注册 | `pc.IDs().Put` 手动注册显式 id | goldmark 的 ids 去重表是包内私有结构，`WithIDGenerator` 是官方提供的扩展点 | 直接实现 `parser.IDs` 接口——接口含 `Put/Generate` 两个方法且需自行去重，绕开官方扩展点反而更繁琐 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| slug 规则与用户文档中既有 href 仍不完全一致（如 `-1` 去重后缀） | 🟢 低 | 用户提供的是自洽样例；slug 规则取主流惯例（GitHub 风格 + 中文保留），常规写法可命中 |
| 改 id 格式影响已有的英文锚点链接 | 🟢 低 | 英文纯 ASCII 标题在新旧规则下产物一致（空格/`-`/`_`→`-`、小写），无兼容性变化 |
| 显式 id（`## 标题 {#custom}`）被覆盖 | 🟢 低 | 自定义生成器仅作用于无显式 id 的标题，`{...}` 语法与 BeforeID 顺序均与原生一致 |
