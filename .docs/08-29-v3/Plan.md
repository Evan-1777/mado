## 1. 背景与目标

现状：命令行未携带文件启动时，前端回退打开「上次打开的文件」（settings.json 的 `lastfile`，首次运行时写入欢迎文档 welcome.md 并打开）。

目标（Interview 已确认）：

- 无文件启动（首次/日常）一律打开**空白未命名新文档**，标题栏显示 untitled，与 Ctrl+N 行为一致。
- 带文件启动但文件读取失败（被删/无权限）时，同样回退空白未命名文档并给出状态提示。
- 首次启动不再生成 welcome.md，欢迎文档机制整体退役。
- lastfile **记录逻辑保留**（打开/保存仍写入），仅启动不再读取，为将来「恢复上次会话」选项留数据；因当前无读取方，须在写入处与文档中明确标注，避免被误判为活跃逻辑。
- 带文件启动（文件关联、拖放、Ctrl+O）正常路径行为不变。

## 2. 阶段划分

### Phase 1：启动路径收敛与欢迎文档机制退役

| 项目 | 内容 |
|------|------|
| **输入** | 现有启动链路：前端 init 的启动文件/欢迎文档回退、Go 侧 lastfile 读取与欢迎文档写入机制、欢迎文档常量及关联测试、目录名常量的跨包重复 |
| **输出** | 无启动文件或读取失败时进入空白未命名状态；Go 侧删除欢迎文档机制与对应绑定；lastfile 读写保留并标注当前无读取方；目录名常量收敛为单一来源；新增启动副作用回归测试 |
| **验收标准** | 无文件启动渲染空白文档，运行期间不新增 welcome.md（历史残留文件不做清理）；带文件启动加载目标文件；启动副作用有 Go 自动化测试覆盖；`go vet`/`go test`、前端语法检查与测试、构建全部通过 |
| **风险** | 前端 init() 无 DOM 测试基础设施（前端测试仅覆盖纯逻辑模块），UI 层行为以浏览器人工验证，不纳入自动回归 |
| **关键决策** | 复用现有新建文档流程作为空白态实现（单一数据源，空白文档行为只有一份）；welcome 机制按整体退役处理（删除优于保留死代码）；目录名与存储路径常量以 settings 包为单一来源，消除跨包重复字面量；删除 Go 绑定时同步手补前端绑定副本（本机语法检查依赖仓库内副本） |
