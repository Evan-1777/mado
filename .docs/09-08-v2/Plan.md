## 1. 背景与目标

审计确认上一轮提交仍有四类可直接复现的问题：HTML 属性分隔符可绕过 meta refresh 净化、原子替换会改写符号链接、无头启动检查的对话框状态会跨调用污染，以及开发构建资源准备不对称。渲染调度器还缺少在途异步任务的背压，导致长渲染期间仍向后端提交无效工作。

本轮目标：

1. 保持 `meta refresh` 净化的完整标签与精确属性语义，覆盖 HTML 空白/斜杠分隔形式，同时不误删引号值中的文本。
2. 保存符号链接时替换其真实目标；对悬空链接或无法解析的目标拒绝写入，不把链接静默改成普通文件。
3. 让确认对话框每次打开从空状态开始，令 startup dev-only 检查在当前代码库中可重复通过。
4. 让 dev/build 共用同一份静态资源复制逻辑，并让渲染调度器在 Promise 未完成时合并后续请求。
5. 保留原子保存的核心不变性：目录没有创建/改名权限时不降级为截断覆写；该平台边界通过错误与文档明确，而不是引入可能丢数据的回退路径。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| HTML 净化边界 | 保留完整标签扫描，属性判断使用引号感知解析并接受空白/斜杠分隔 | 在现有渲染后净化模型内修复真实绕过，避免把合法 HTML 全部禁用 | 全量 AST 重写：改动面大且会改变既有 raw HTML 语义 |
| 符号链接保存 | 解析现有链接的真实目标后在目标目录原子替换 | 保留用户链接关系与原子替换不变性；悬空链接拒绝比静默断链安全 | 直接替换链接：会造成数据分流；跨目录临时文件：失去原子改名 |
| 目录无写权限 | 保持失败，不回退到截断覆写 | 原子保存的核心契约是失败时旧内容不变，不能用数据损坏换取表面兼容 | 直接 `WriteFile` 回退：破坏崩溃安全不变性 |
| 资源复制 | 单一 Node 资源脚本由 build/dev 调用 | 消除两条命令的资产清单漂移，同时保持 npm 原生链路 | 继续复制长内联命令：最小表面修复但会保留结构性漂移 |
| 渲染背压 | 调度器以 Promise 完成作为下一次尾随请求的释放点 | 在根调度层合并无效请求，调用方不维护第二套 in-flight 状态 | 在 `refreshPreview` 外层追加调用点标志：状态源分散且容易漏掉主题/启动路径 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| HTML 属性语法复杂，过宽正则可能误删属性值中的文本 | 🔴 高 | 在完整标签边界内按引号状态扫描属性；新增正向/负向回归样例 |
| 符号链接解析与最终改名之间存在外部进程竞态 | 🟡 中 | 收窄为单进程常规保存的最佳努力；不宣称跨进程锁定；悬空/解析失败直接返回错误 |
| Promise 背压改变高频输入的刷新时序 | 🟡 中 | 维持 `renderVersion` 过期响应保护，加入在途合并单测，保留最小 80ms 间隔 |
| 资源脚本改变本地 dev 初始目录创建顺序 | 🟢 低 | 脚本先创建目标目录再复制文件，并用 build 与 dev 前置检查验证 |
| 只写文件权限但目录不可写的用户场景仍无法原子保存 | 🟡 中 | 明确记录为原子替换的目录权限前置条件，继续返回错误，不引入数据破坏性降级 |
