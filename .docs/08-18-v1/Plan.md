## 1. 背景与目标

根据用户提出的三项核心需求：
1. **窗口缩放修复**：修复 Windows 下无边框窗口只能在左上方调整大小、右下方（以及右侧、底部、右下角等）无法调整窗口大小的问题。
2. **目录栏重构与性能深度优化**：深度优化目录解析与渲染性能；移除缩进排版，改为使用多级深浅颜色（Dark / Light 双主题色彩深度）表示 H1~H6 层级所属关系。
3. **标题栏图标与按钮样式重构**（基于 `image.png`）：替换 Open、Save 等与功能不符的图标为规范 SVG 矢量图形，取消文字标签，保留纯图标按钮并对齐 Win11 标题栏风格。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 窗口缩放机制 | 前端视口边缘精准判定 + `WailsInvoke("resize:" + edge)` + 跨 iframe 事件捕获 | Wails 内部通过 `outerWidth - clientX` 计算边缘，在 Windows WebView2 下因系统不可见边框导致右/底边界判定永远不成立；且 iframe 阻断鼠标事件。前端统一接管可实现全边缘无死角缩放 | 修改 Go 内部 Wails 库代码（侵入第三方 mod，不可持续）；仅调大 `borderThickness`（仍然受 outer 偏移影响且手感粗糙） |
| 标题栏图标 | 内联 SVG 图标系统 | 零外部字体/网络依赖，离线可用，暗/亮模式自适应 `currentColor` | 图标字体（引入额外加载开销与 FOUT）；外部图片文件（额外 IO 开销） |
| 目录层级呈现 | Flat 扁平排版 + 多阶色彩深度令牌（`--toc-h1` ~ `--toc-h6`）+ 醒目级别标识 | 彻底摆脱深层缩进导致的文字挤压与折行，色彩与字重层级直观高级，完美符合用户要求 | 仅移除 padding 不加色彩区分（无法直观区分层级）；仅使用点线连接（依然有缩进或视觉噪音） |
| 目录性能优化 | 惰性计算 + 标题签名哈希跳过 + 单一事件委托 + 局部状态切换 | 避免每次键入 100ms 销毁重建整个目录树；Split 模式不浪费渲染计算；事件委托减少 DOM 监听器数量 | 引入虚拟滚动库（增加包体积与复杂性，对于 TOC 属于过度设计） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 跨 iframe 鼠标移动可能在快速划过时丢失边缘状态 | 🟡 中 | 在 parent window 与 preview iframe 同时监听 mousemove 与 mouseleave，建立全局状态统一重置 |
| 目录色彩在亮色模式下 H5/H6 对比度过低影响可读性 | 🟢 低 | 经过 WCAG 对比度校验的梯度调色，H5/H6 保持在可读灰度，hover 时高亮提示 |
| 目录结构在编辑过程中可能未触发更新 | 🟢 低 | 采用基于标题文本与行号的签名比对，签名变化时精准更新 |
