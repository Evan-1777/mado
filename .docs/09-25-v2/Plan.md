# Plan：修复审查报告遗留问题

**状态**：DONE
**日期**：2026-09-25
**版本**：v1.0

---

## 1. 背景与目标

本轮针对目录解析与折叠状态的两个遗留问题做小范围修正。围栏识别按标记字符和长度判断闭合；ATX 标题解析保留标题文本中未由空格引出的井号；重复标题折叠状态按层级、文本和同层同名标题出现序号区分。

审查还指出并发主题更新存在理论上的绑定调用顺序竞态。但现有前端在一次主题调用完成前不会更新主题状态，用户操作生成的并发调用目标相同；原生窗口又是无边框窗口，未见当前用户可达的差异场景。因此本计划不为该竞态增加互斥量、测试注入接口或并发用例，也不调整主题设置路径。

## 2. 阶段划分

### Phase 1：修正并验证目录解析（P0）

**输入**：现有目录解析行为与前端零依赖自检。

**产出**：可独立测试的目录解析逻辑正确识别围栏边界与 ATX 标题文本。

**验收标准**：自检覆盖反引号围栏中的波浪号行、短于开围栏的闭合候选、正确闭合后标题入目录，以及 C#、F#、Part # 标题文本保留；前端自检通过。

### Phase 2：修正并验证重复标题折叠状态（P1）

**输入**：标题目录与现有折叠状态恢复行为。

**产出**：同层级同名标题可独立保留折叠状态。

**验收标准**：确定性自检验证两个重复标题状态独立，并在目录重建后按出现序号分别恢复；前端自检通过。

### Phase 3：更新项目说明并执行回归（P0）

**输入**：目录解析与折叠状态修正结果。

**产出**：项目目录结构、测试清单、目录解析行为和决策记录与实际状态一致。

**验收标准**：前端自检与构建、Go vet、Go 常规测试及竞态测试通过；Go 验证使用临时 GOCACHE 并在结束时清理，避免依赖只读的默认缓存目录。

## 3. 范围与取舍

- 不以组合根文件长度为由拆分前端主流程，不更改 HTML 渲染策略，不增加依赖。
- 围栏解析仅实现目录所需的标记符、长度和独立闭合行判断，不扩展为完整 CommonMark 解析器。
- 重复标题状态使用同层级、同文本的出现序号区分，不建立跨编辑稳定身份系统；文档结构变化导致序号变化时允许状态按当前顺序重新关联。
- ATX 标题末尾两个及以上井号仅在前有空格时作为闭合标记；单个结尾井号保留为标题文本，以满足 C#、F#、Part # 等目录文案的预期；不改写其他标题语法或渲染行为。
- 并发主题竞态当前没有不同值的用户可达调用路径，故不加入生产锁、测试 seam 或专门并发测试；若前端调用模型改变，再根据实际可达性复核。

## 4. 风险清单

| 风险 | 缓解措施 |
|------|----------|
| 轻量目录解析与完整 Markdown 语法仍有差异 | 将验收边界限定于围栏闭合及 ATX 标题文本，使用实际样例自检，不引入完整解析依赖 |
| 以出现序号恢复重复标题状态，插入同名标题可能改变后续映射 | 明确接受按文档顺序重新关联，不维护复杂跨编辑身份 |
| 默认 Go 构建缓存目录在执行环境只读 | 验证时使用临时目录作为 GOCACHE，并在命令结束时清理 |
