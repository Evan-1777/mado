**版本**：v1.4.1  
**回归测试结论**：前端语法检查通过，npm build 产出正常（527KB app.js + 7.3KB app.css），go vet/test 全部通过，无回归问题。

## 1. 背景与目标

用户报告目录栏存在两个问题：
1. 大量包含 `#` 标题的文档仍显示"当前文档没有标题"
2. 缺少侧边栏整体折叠/展开功能

排查发现 `parseToc` 函数使用了字面量 `split('\\n')`（反斜杠+n），导致整个文档被当作单行处理，标题正则匹配失败。

本次计划修复标题解析 bug 并添加侧边栏折叠交互。

## 2. 阶段划分

### Phase 1：定位与修复标题解析 bug

| 项目 | 内容 |
|------|------|
| **输入** | 用户报告的示例文档（大量标题但目录为空） |
| **输出** | 修复后的 `parseToc` 函数，正确识别换行符 |
| **验收标准** | 示例文档能正确显示多层目录树 |

### Phase 2：添加侧边栏折叠交互

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 修复后的目录解析逻辑 |
| **输出** | 侧边栏头部折叠按钮 + CSS 动画 + 状态切换逻辑 |
| **验收标准** | 点击按钮侧边栏收缩至 40px，再点击展开回 248px，过渡平滑 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 修复方式 | 直接改 `split('\\n')` 为 `split('\n')` | 一字之差，影响范围明确，无副作用 | 重写 parseToc 逻辑（过度工程） |
| 折叠方式 | CSS class toggle + flex-basis 动画 | 性能好，无需 JS 计算尺寸，过渡自然 | JS 动态修改 width（更多重排） |
| 按钮位置 | 侧边栏头部左侧 | 符合 Windows 11 设计惯例（折叠按钮在边缘） | 工具栏（位置不直观） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 换行符修复可能影响 fenced code 跳过逻辑 | 🟢 低 | 逻辑已存在，仅修复分割方式，fenced 状态不受影响 |
| 折叠动画在低性能设备卡顿 | 🟢 低 | 仅 flex-basis 动画，GPU 友好，且用户可禁用 reduced-motion |
| 折叠状态未持久化，刷新后丢失 | 🟡 中 | 本次不实现，标注为已知限制，后续可用 localStorage |
