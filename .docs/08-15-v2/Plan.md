## 1. 背景与目标

编辑器和预览全屏模式目前只有单栏内容，长文档需要依靠滚动定位。本次为两个全屏模式增加统一的左侧目录侧栏：读取 Markdown 标题形成多层级树，默认折叠，支持逐级展开/折叠、全部展开和点击标题跳转；侧栏显示时内容区域向右收缩，分栏模式保持现有布局。

## 2. 阶段划分

### Phase 1：目录模型与全屏布局

| 项目 | 内容 |
|------|------|
| **输入** | 当前 Markdown 文本、editor/preview 模式切换 |
| **输出** | 共享目录侧栏 DOM、标题层级模型、全屏布局样式 |
| **验收标准** | 仅 Editor/Preview 全屏模式显示侧栏；Split 模式不显示；无标题时侧栏给出空状态 |

### Phase 2：折叠交互与双向跳转

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的目录模型与布局 |
| **输出** | 默认折叠、节点展开/折叠、全部展开、目录项跳转 |
| **验收标准** | 多层标题按父子层级显示；点击 Preview 项滚动到对应标题；点击 Editor 项滚动并定位到对应 Markdown 标题；更新文档后目录同步 |

### Phase 3：验证与文档维护

| 项目 | 内容 |
|------|------|
| **输入** | 前两阶段实现 |
| **输出** | 前端构建验证、Project.md 更新 |
| **验收标准** | esbuild 语法检查、npm build、go vet、go test 全部通过；Project.md 与实现一致 |

## 3. 架构决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 目录数据源 | 前端从 Markdown ATX 标题解析 | 不新增后端绑定；编辑器跳转需要原文行号，预览可通过标题 id 映射 |
| 目录组件 | Vanilla TypeScript 共享 DOM/事件逻辑 | 项目无前端框架，避免为简单树状导航增加依赖 |
| 全屏识别 | 复用现有 `editor-only` / `preview-only` 模式类 | 保持 Split 模式零变化，减少布局状态分叉 |
| 折叠策略 | 根目录默认折叠，父节点控制子节点可见性；“全部展开”一次展开全部节点 | 符合长文档快速浏览需求，交互可预测 |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 标题解析误把 fenced code 中的 `#` 当标题 | 🟡 中 | 解析时跳过围栏代码块 |
| 预览标题 id 与前端 slug 不一致导致跳转失败 | 🟡 中 | 目录项保存标题文本，渲染后从 iframe 标题节点读取实际 id，并以文本匹配绑定 |
| 大文档频繁重建目录影响编辑流畅度 | 🟢 低 | 仅在 Markdown 内容变化后的渲染链路中更新目录，采用一次 DOM 重建 |
