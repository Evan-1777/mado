# Plan：设置面板响应、标题栏图标与公式渲染解析缺陷修复

**状态**：DONE  
**日期**：2026-08-19  
**版本**：v1.0  
**回归测试结论**：全部 5 个 Go 包单元测试（含单行/多行公式尾随空白容错与结构隔离、行内公式解析等全部用例）无缓存全绿通过（-count=1），前端 esbuild 语法检查零错误，全链路构建验证完成，无回归问题。

---

## 1. 背景与目标

在 v1.5 版本引入 LaTeX 数学公式与设置面板后，发现了三个关键交互与渲染缺陷：
1. **设置按钮无 UI 响应且锁定应用**：由于 `index.html` 中 `#close-dialog` 遗漏 `</dialog>` 闭合标签，导致 `#settings-dialog` 被解析为未开启对话框的子节点，调用 `showModal()` 时弹出不可见的顶层模态并捕获全局事件，造成应用假死。
2. **标题栏设置图标失真（image.png 标记 1）**：`GLYPH_SETTINGS` 矢量路径齿轮形状不规则且线条不匀称，需规范为标准 Lucide 风格的清晰矢量齿轮。
3. **LaTeX 单行/行内公式解析穿透破坏 Markdown 结构（image.png 标记 2）**：`mathBlockParser` 对单行 `$$...$$` 的尾随空白（空格/制表符）缺乏容错且未记录单行闭合状态，导致单行公式在后续行触发 `Continue` 将全文（标题、分割线、段落）全部吞入公式块并在 KaTeX 解析错误时通篇报红；同时 `mathInlineParser` 需支持行内 `$$...$$` 解析。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 对话框层级结构 | HTML 根部同级原生 `<dialog>` | 遵循 HTML5 标准顶层元素规范，维持 Esc/焦点囚禁独立性 | 将设置面板改为自定义 `<div>`（失去原生 top-layer 优势） |
| 标题栏设置图标 | Lucide 风格 15x15 矢量 SVG | 与现有 Open/Save/New/Theme 保持 1.8 描边与圆角风格统一 | 引用外部图标字体（破坏零外部运行时依赖原则） |
| LaTeX 边界处理 | Go 端 Parser 尾随空白清洗 + 状态上下文跟踪 | 在数据流源头解决块解析状态逃逸，彻底杜绝语法穿透 | 在前端 KaTeX 渲染处截断（治标不治本，Markdown AST 依然损坏） |
