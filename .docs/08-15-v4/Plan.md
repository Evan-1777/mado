## 1. 背景与目标

预览目录点击已被父页面拦截，但中文 fragment 经 Markdown 渲染后会百分号编码，而标题 DOM id 保持 Unicode。当前逻辑用编码文本直接查找 id，导致目标不存在且点击无反馈。

本次目标是按 URL fragment 语义解析目录链接，使中文、空格和 ASCII 锚点都能命中标题，同时保留 iframe 禁止导航的安全边界。

## 2. 阶段划分

### Phase 1：修正锚点目标解析

| 项目 | 内容 |
|------|------|
| **输入** | 预览 iframe 中经 HTML 编码的 fragment 链接 |
| **输出** | 解码后的 DOM id 查找与滚动行为 |
| **验收标准** | 中文百分号编码 fragment 可命中 Unicode id；非法编码不抛异常；非 fragment 链接仍被阻断 |

### Phase 2：回归验证与文档同步

| 项目 | 内容 |
|------|------|
| **输入** | 修正后的预览链接处理和真实中文目录样例 |
| **输出** | 自动化回归结论与更新后的项目约束记录 |
| **验收标准** | 前端语法构建、Go 测试和 vet 全部通过 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| fragment 解析 | 点击时使用平台 URL 解码能力 | 与浏览器 URL 语义一致，改动集中在实际失配位置 | 改写标题 id 为百分号编码（DOM id 不应承担 URL 序列化格式） |
| 失败处理 | 保留原 fragment 作为回退 | 畸形链接不应中断后续点击处理 | 直接抛错（会使监听器行为不可预测） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| fragment 含字面 `%` 导致解码异常 | 中 | 捕获解码错误并回退原值 |
| 修复中文后破坏 ASCII 锚点 | 低 | 保留 ASCII 用例并执行前端构建 |
