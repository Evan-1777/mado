# Plan：支持自定义 Preview 字体

**状态**：DONE（2026-08-24 完成；回归：go vet/test、esbuild、npm run build、git diff --check 全部通过）  
**日期**：2026-08-24  
**版本**：v1.0

## 1. 背景与目标

当前 Preview 的正文、行内代码和键盘标记使用硬编码的等宽字体栈，用户无法根据本机已安装字体调整阅读效果；主题、自动换行和公式渲染已经具备独立的偏好持久化与即时应用链路。

本阶段新增 Preview 字体设置，目标如下：

- 用户可输入一个本机字体名称作为 Preview 首选字体。
- 保留现有字体栈作为固定回退，未安装首选字体时仍能正常显示。
- 设置可持久化，旧版配置缺少新字段时保持现有默认外观。
- 字体修改成功后立即刷新 Preview，且不重载 iframe、不影响编辑器字体。
- 在 CSS 注入边界校验和转义字体名称，避免用户配置破坏 Preview 样式。

非目标：字体发现、字体安装、网络字体加载、字体文件导入、编辑器字体自定义，以及允许用户输入完整 CSS `font-family` 表达式。

## 2. 阶段划分

### Phase 1：偏好模型与持久化

| 项目 | 内容 |
|------|------|
| **输入** | 现有主题、自动换行、公式渲染偏好与共享 JSON 存储机制 |
| **输出** | Preview 字体字段、默认值、合法性边界及向后兼容的读写逻辑 |
| **验收标准** | 新字段可保存并重新加载；旧配置继续使用当前默认值；非法类型或不符合边界的值不会进入有效设置 |

### Phase 2：Preview CSS 字体注入

| 项目 | 内容 |
|------|------|
| **输入** | 已校验的 Preview 字体偏好与现有亮/暗主题 CSS 组合流程 |
| **输出** | Preview 样式使用可配置字体变量，正文与现有等宽内容保持一致的字体语义 |
| **验收标准** | 两个主题都能生成包含自定义字体与固定回退栈的 CSS；默认值下视觉字体栈与现状等价；无效主题仍返回错误 |

| 项目 | 内容 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 字体输入模型 | 单个本机字体名称 | 需求是自定义首选字体，固定回退栈可继续提供可读性；模型简单且边界清晰 | 完整 CSS 字体表达式（扩大输入面并增加 CSS 注入与解析复杂度） |
| 回退策略 | 首选字体前置，保留现有字体栈 | 未安装字体时无需探测或下载，离线行为稳定 | 仅使用用户输入（字体缺失时可能退化到浏览器默认字体） |
| 状态来源 | Go Settings 作为持久化单一来源，前端只维护显示/刷新状态 | 与现有主题、换行、公式偏好契约一致，重启后行为一致 | 前端 localStorage（与便携化 settings.json 分裂） |
| CSS 应用方式 | Preview CSS 注入字体变量，复用现有 `GetCSS` 缓存失效与 iframe 原地更新 | 不新增运行时依赖，不重建 Preview 文档，不影响编辑器字体 | 前端直接改 iframe style 或重设 `srcdoc`（会破坏现有滚动保持模型） |
| 输入安全边界 | Go 侧裁剪空白、限制长度、拒绝控制字符与 CSS 结构分隔符，并在 CSS 字符串中转义 | 设置文件和 Wails 绑定都是信任边界，校验集中且可测试 | 仅依赖前端校验（可被绕过，且绑定调用仍可能传入危险值） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 用户输入的字体未安装 | 🟢 低 | 固定回退栈；本阶段不做字体探测和安装 |
| 旧版 settings.json 缺少字段 | 🟢 低 | 缺失字段回退到当前首选字体默认值，保存时保留无关顶层字段 |
| CSS 注入导致样式破坏 | 🟡 中 | Go 侧统一校验输入边界，主题层负责 CSS 字符串转义，并添加单测 |
| 设置保存失败后前端显示值与后端不一致 | 🟡 中 | 仅在绑定调用成功后更新本地状态和刷新 Preview；失败时恢复上一次有效输入 |
| Preview CSS 缓存未失效 | 🟡 中 | 字体变更与主题变更使用同一缓存失效入口，并用语法检查和手动链路验证 |
