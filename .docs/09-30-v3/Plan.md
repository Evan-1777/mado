## 1. 背景与目标

项目文档模板规范已由旧版编号结构升级为更加规范克制、按名称扁平引用的设计。当前项目主参考文档存在章节带数字编号、目录与架构说明割裂分散、混杂了大量历史任务补丁日志、本应置末的维护速查表当前被置顶在首节且充斥跨节符号引用等脱节现象。

本次计划将项目单一事实来源文档按照最新规范要求进行整体重构与更新，实现以下目标：

- 章节结构完全对齐最新规范，移除全部章节数字编号与过时的跨节符号引用。
- 整合目录职责与架构数据流为统一的结构章节，提炼核心数据流与架构依赖红线。
- 概述明确一句话定位，非目标保留内联清单并引述设计原则，杜绝信息丢失。
- 合并已知约束与技术决策，建立去重与保底提取机制：过滤任务级叙事性日志，完整保留确立的长期实现契约。
- 省略无外部服务的空章节，将维护速查表按新规范字段更新并置于文档末尾。
- 严格遵循单一事实来源，环境类坑内联 ★ 现象，深层原因统一归入约束与决策，非环境 ★ 转换为规则——原因。

## 2. 阶段划分

### Phase 1：文档骨架重排与概述/环境运行对齐

| 项目 | 内容 |
|------|------|
| **输入** | 新文档模板规范、现行主文档概述与环境配置内容 |
| **输出** | 规范的文档前言、一句话定位、非目标内联清单与环境运行章节草案 |
| **验收标准** | 章节按名称组织无编号，概述非目标保留多标签/插件/导出/Mermaid清单，环境易错点按 ★ 标出操作现象 |

### Phase 2：结构与约定章节合并重组

| 项目 | 内容 |
|------|------|
| **输入** | 现有目录职责、架构数据流、依赖规则及项目约定 |
| **输出** | 统一的结构章节（含目录树职责、核心数据流、依赖方向）与约定章节 |
| **验收标准** | 目录树关键项一行职责清晰，数据流按场景归纳收敛，依赖方向红线明确，约定具体可执行 |

### Phase 3：约束决策提炼与术语/维护表重组

| 项目 | 内容 |
|------|------|
| **输入** | 现行主文档全文约束、已知坑、历史决策、术语定义与维护速查表 |
| **输出** | 去重提炼后的约束与决策章节、术语表与末尾维护表 |
| **验收标准** | 提炼全量长期契约（规则——原因格式），过滤叙事性补丁日志，非环境 ★ 转换到位，术语定义精准，维护表置底对齐 |

### Phase 4：文档一致性审计与自检

| 项目 | 内容 |
|------|------|
| **输入** | 重构后的完整项目单一事实来源文档 |
| **输出** | 无死引用、无双源漂移、契约完备的正式文档 |
| **验收标准** | 对照模板结构逐节核对无遗漏，全文无旧章节数字引用，格式排版符合规范 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 非目标定义方式 | 保留内联清单并附 SCOPE.md 引用 | SCOPE.md 仅有设计总原则，未具体列出多标签/插件/导出/Mermaid 等非目标清单，直接仅写引用会导致唯一记录丢失 | 仅写「详见 SCOPE.md」（导致非目标信息彻底遗失） |
| 环境坑与约束去重（SSOT） | 环境节只留操作层 ★ 现象，原因与架构契约归入约束与决策 | 避免同一契约在环境节与约束节两处复制，消除双源维护与漂移风险 | 两处均完整叙述（违背单一事实来源） |
| 星号标记适用范围 | 仅环境类坑保留 ★；非环境类保留内容、移除 ★ 标记，按「规则——原因」归入约束与决策 | 新模板明确规定 ★ 仅用于「环境与运行」节内联易错点，正文其他部分应保持规范列表 | 全量保留 ★（违背新模板分类法）或将非环境 ★ 迁入环境节（破坏职责划分） |
| 历史记录过滤与保底提炼 | 过滤叙事性审阅/补丁过程，但提取条目内确立的长期实现契约（如 needFree 内存管理、CM 视口机制等） | 阶段归档已完整记录微观流水账，项目主文档应聚焦长期有效契约，但绝不能误删关键物理限制与实现边界 | 全量保留流水账（造成文档膨胀）或机械整条删除（导致重要契约灭失） |
| 外部集成章节处理 | 完全省略 | 本项目为本地离线桌面应用，无外部云端服务或三方 API | 保留空章节（违背模板「无内容章节直接省略」原则） |
