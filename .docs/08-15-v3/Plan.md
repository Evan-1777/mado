## 1. 背景与目标

用户在预览界面点击 Markdown 文档内的目录（TOC）锚点链接（如 `[Section](#section)`）后，预览区整体黑屏且无法恢复（除非再次编辑触发重渲染）。

**根因**：预览 iframe 采用 sandbox（仅 allow-same-origin，无 allow-scripts）+ srcdoc 首帧引导 + 帧内原地更新的模型。点击锚点链接时，渲染引擎将 `about:srcdoc#fragment` 视为一次新的 iframe 导航而非同文档锚点滚动，帧内文档被替换为空文档（无样式、无内容），暗色主题下表现为黑屏。纯预览模式下没有后续编辑，重渲染回退路径不会被触发，黑屏持续。

**目标**：

- 点击目录/锚点链接后预览平滑滚动到对应标题，不再黑屏
- iframe 不发生任何导航（保持原地更新模型不变）
- 外部链接点击同样不得把预览帧导航走（同类根因，一并阻断）
- 不放宽 sandbox（维持无脚本安全模型）

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 拦截位置 | 父页面监听帧内 document 的 click | sandbox 无 allow-scripts，帧内无法运行脚本；allow-same-origin 允许父侧跨帧 DOM 访问 | 帧内注入脚本（需放宽 sandbox，破坏安全模型） |
| 锚点滚动 | preventDefault + 目标元素 scrollIntoView | 阻止导航后手动滚动是唯一可行路径；平滑滚动符合预览体验 | 依赖原生锚点行为（即本 bug 根源） |
| 监听器生命周期 | 挂在帧 load 事件，每次帧文档重建后重挂 | srcdoc 引导/回退会销毁旧 document 与监听器；原地更新不销毁 document，监听器天然保留 | 每次渲染都重挂（多余）；CSS 注入（不可行） |
| 外部链接处理 | 一律 preventDefault（点击无动作） | 任何 iframe 导航都会毁掉原地更新模型（同一根因）；本地查看器场景外链非核心诉求 | 用系统浏览器打开外链（需新增 Go 绑定，超出本 bug 范围，YAGNI） |
| 目标查找 | 按 href 字面量取 id 查元素 | 渲染引擎输出的 href 与标题 id 均为字面量，直接匹配 | 引入 URL 解码（渲染输出不含编码形式，无必要） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 跨 realm 判断失误：父窗口的 Element 与帧内元素不满足 instanceof | 🟡 中 | 用节点查询 API（closest）替代 instanceof 判断，跨 realm 安全 |
| 黑屏已发生的存量会话中监听器缺失 | 🟢 低 | load 重挂 + 渲染回退路径重建 srcdoc 后监听器自动恢复 |
| 目标 id 不存在（悬空锚点） | 🟢 低 | 查不到目标时仅阻止导航不滚动，行为安全 |
| 平滑滚动在低端机顿挫 | 🟢 低 | WebView2 环境统一（Edge 151），风险极低 |
